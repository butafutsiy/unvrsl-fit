# Индивидуальные нагрузки v540

База приложения сохранена на v538. В WorkoutDomain добавлены индивидуальные политики коррекции нагрузки; новый независимый движок и миграция истории не вводятся.

## Покрытие каталога

Проверены все 189 действующих ID:

- 165 записей с развёрнутыми независимыми настройками реакции;
- 16 упражнений без внешнего веса;
- 5 записей для отдельных обработчиков времени/прыжков/рывка;
- 3 записи с конфликтом метаданных: `og:0009`, `og:0011`, `og:0795`.

`exercise-load-policies.js` содержит явную запись для каждого ID. Проценты являются стартовыми продуктовыми настройками. Физические ряды оборудования пользователя не выдумываются: доступные веса выбранного оборудования имеют приоритет над его шагом и запасным шагом каталога. Запасной шаг явно отмечен в объяснении.

## Реакция и оборудование

У каждого упражнения свой вектор L1/L2/H1/H2/H3, процентные потолки, пределы количества ступеней и допуск RPE. `equipmentProfile.correctionPolicy` переопределяет эти значения только для выбранного оборудования данного упражнения. Профили оборудования сохраняют существующую привязку `exerciseKey`.

L1/L2 повышают нагрузку после верхней границы повторов; H1/H2/H3 облегчают подход при возрастающем превышении усилия или недоборе. Реальный вес выбирается из ряда оборудования как ближайший к желаемой коррекции в пределах индивидуальных ограничений. При одинаковой близости выбирается меньшее изменение. При недоступной ступени вес сохраняется с объяснением.

Для цели RPE 7–8 и ряда через 2,5 кг присед 100 кг даёт 95/92,5/90 кг после RPE 9/9,5/10. Жим 80 кг на том же шаге даёт 77,5/75/75 кг. Отличаются величины реакции, а не только минимальные шаги.

Гравитрон обращает направление цифры: меньше помощи означает большую нагрузку. Дополнительное отягощение хранится отдельно от тела; для новой процентной коррекции требуется известная масса тела. Изменение режима нагрузки не выполняется молча.

В «Оборудование» добавлены параметры реакции в раскрывающемся блоке. Пустые поля и недопустимые/неупорядоченные проценты не сохраняются. Три спорные записи требуют ручного подтверждения типа нагрузки и явной политики; до этого новые рекомендации заблокированы.

## Усилие и сохранность

RPE 0 означает отсутствие оценки; RIR 0 является валидным максимальным усилием. Противоречие RPE/RIR не разрешает повышение. Недобор повторов при низком усилии требует уточнения. Ручные назначения, завершённые/пропущенные сеты и история не переписываются.

Сдвиг целевого RPE применяется только к известному наследованию (`effortTargetSource: week_inherited`). Сохраняются исходные `effortBaseMin/Max`, чтобы рендер и перезагрузка не сдвигали цель повторно. Ручные цели и старые цели неизвестного происхождения сохраняются. Разгрузка, тесты, back-off и специальные методы используют существующую логику.

Недельное `calculatedWeight` остаётся результатом прежнего e1RM и процентов недели. Новая `nextSetSuggestion` имеет явный `policyVersion`, применяется отдельно и не заменяет недельный расчёт. Между тренировками новая прибавка требует полной сопоставимой серии на верхней границе повторов минимум из двух сетов.

## Проверки

```sh
node --test tests/*.test.cjs
node scripts/audit-load-policies.cjs
node scripts/audit-exercises.cjs --strict
node scripts/build-static.cjs
```

Новые тесты проверяют все ID, разные физические машины, несколько ступеней приседа, грубые/неравномерные ряды, RPE/RIR, происхождение целей, отдельный недельный расчёт, обновление незавершённых снимков оборудования и сохранность истории. Выпуск PWA использует единый кэш v540.
