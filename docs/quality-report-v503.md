В основной базе: 52 блюда с говядиной, 27 со свининой, 58 с птицей, 46 с рыбой, 88 завтраков, 26 новых супов, 22 салата, 24 бутерброда/перекуса; 15 бургеров, сэндвичей и шаурм. Категории пересекаются. Составы сравнивались также после нормирования граммовок, чтобы одинаковая порция другого размера не считалась новым рецептом.

835 продуктов взяты из официального архива USDA SR28, 4 позиции из официальной маркировки производителя «Простоквашино». SR28 является историческим справочником, а не маркировкой современных российских товаров. В данных сохранены исходный код, название, состояние, основа 100 г, источник, жиры и опубликованная энергия. Углеводы USDA включают клетчатку. Для своей марки нужна проверка упаковки. Подробности и контрольные суммы: `data/nutrition/SOURCES.md`, `import-manifest.json`.

Новые рецепты написаны для приложения. Калории и БЖУ рассчитываются из состава, а не копируются с похожего блюда. Выход и удержанное масло являются допущениями: выход обозначен как оценочный, масло учитывается целиком. Измеренный готовый вес заменяет оценку и используется для доли порции. Штуки требуют измеренной или явно оценочной массы.

В старом описании свинины была неточная ссылка на выпуск USDA. Для новых расчётов используется NDB 10060 из SR28. Старые значения записанного питания сохранены. Остаточные «усреднённые овощи» в шаблонах заменены конкретными продуктами и граммами.

Импорт повторяемый: продукты обновляются по NDB ID; сохранённые ингредиентные ID остаются алиасами. При повторном выполнении генераторов содержимое и количество не меняются. Каталог не вносится в личную историю и не требует SQL-миграции.

## Проверки и границы

Проверки выполняются на отдельных фикстурах. Реальная история аккаунтов не редактировалась. Все таблицы проекта имеют RLS. Проверена серверная изоляция: неизвестный authenticated UID получает 0 планов, 0 тренировок и 0 состояний аккаунта; anon не имеет доступа к user_app_state. Серверный триггер обновления updated_at подтверждён. Права и SQL-схема не изменялись.

Проверяются все Node-контракты проекта, JavaScript-синтаксис, строгий каталог упражнений, новый аудит питания и сценарии DOM из GitHub Actions. Отдельно проверены рецепт/выход/порция/запись, правка рецепта после записи, перезагрузка, десятичная запятая, штуки, отказ от неявного перевода мл в г, откат при ошибке сохранения, конфликт синхронизации, исключения, разнообразие меню, поздний вход, таймер и завершение тренировки, восемь недель цикла, история и изображения «Поделиться».

В репозитории нет отдельной сборки TypeScript: это статическое приложение JavaScript. Поэтому предусмотренные проверки включают node --check, node --test и DOM-сценарии; публикация выполняется штатным GitHub Pages workflow.

Доступный браузер: Chrome в облачной среде, экран 1351 × 948. Safari на iPhone, физическая экранная клавиатура и аппаратные размеры 320–430 px недоступны. DOM-симуляция и CSS-проверки не выдаются за испытание на iPhone. Реальный повторный вход в личный аккаунт не проверен без предоставленной браузерной сессии; поздняя авторизация и восстановление данных проверяются фикстурами и серверными политиками. Одновременное редактирование одного и того же рецепта выбирает последнюю отметку изменения; разные записи и удаления сливаются отдельно.

## Уточнения по скриншотам пользователя

В v504 исправлен порядок карточек под силовым графиком: та же хронология, что на графике, от старых слева к последней справа. Индексы выбранных точек и математические значения не меняются. Проверяется общая семья оборудования и отдельный тренажёр.

Верхние категории выбора блюд: «Завтрак», «Обед», «Ужин», «Перекус». В замене по умолчанию выбран текущий приём. Поиск по говядине и другим ингредиентам перенесён в раскрываемый фильтр. В итоговой v509 категории приёма пищи находятся только в рецептах; продукты фильтруются ингредиентными подсказками на месте.

Настройки: переключатели на отдельной строке, равные области нажатия, кнопка «Синхронизировать» не разбивается внутри слова. В форме общедоступного прогресса дата на узком экране занимает отдельную строку. Последнее пожелание пользователя: подпись нижней навигации видна только у выбранного пункта; постоянные подписи не добавляются.

В v505 выбранные сегменты темы и схемы тела используют контрастный цвет действия, вторичные подписи используют общий цвет текста. Контролы главной дополнительно проверены в v507 по их фактическим классам sd2/bw190.

В v506 устранён подтверждённый браузером приоритет старого правила светлой темы над семантическим цветом выбранных переключателей.

Браузер v506 подтвердил фактический контраст переключателей 4,86:1, белый текст на rgb(159,75,201). В v507 ссылка цели, запись веса и история используют этот цвет действия; области нажатия и переключатели периода имеют высоту 44 px.

## Фильтры и цель на клиентской странице · v508

Ингредиентные подсказки содержат отдельные продукты; «Бургер» удалён, добавлены рис, булгур, картофель, овсянка, фасоль и другие продукты. Бургеры доступны через обычный поиск и тип блюда. Поиск ингредиента сохраняет тип питания, приём пищи, время и вид блюда. Выбор категории приёма пищи также сохраняет остальные условия. Явный сброс синхронизирует все поля и чекбокс мировой подборки. В раскрытом фильтре виден текущий счётчик результатов. Рыбные блюда с новыми ID USDA учитываются в фильтре «Без мяса, с рыбой»; тип собственных блюд определяется по общим правилам.

На общедоступной клиентской странице цель прежде отображалась лишь в карточке. Теперь она передаётся в график, рисуется пунктиром и имеет подпись. Вертикальная шкала включает целевой вес. Цель не добавляется к измеренным точкам и не меняет минимум, максимум, среднее или историю. Тестовый сценарий проверяет набор, снижение, достигнутую цель, крайние допустимые цели, одну запись и отсутствие/недопустимость цели. Права доступа и API не менялись.

## Устранение повторов фильтров · v509

По последним скриншотам устранены три вывода одного приёма пищи: верхняя строка категорий, плитки внутри фильтров и селектор. Осталась одна строка «Завтрак / Обед / Ужин / Перекус». Нажатие выбранного пункта в общем каталоге снимает ограничение по приёму. Остальные фильтры и поиск сохраняются; сброс виден рядом с активными условиями. Раскрытие дополнительных фильтров не создаёт второго выбранного приёма.

В продуктах нет категорий приёма пищи. Каждая ингредиентная подсказка выведена один раз. «По ингредиентам» больше не выглядит как пустой раздел при закрытом details: продукты видны сразу и прокручиваются горизонтально внутри ряда. Общие фильтры «Все продукты / Недавние / Мои / Молочное / Крупы» находятся отдельно; их выбор начинает просмотр соответствующей группы, очищая предыдущий поисковый запрос.

Выбор категории при замене блюда обновляет результаты на том же экране и не уводит в общий каталог. Если выбран другой приём для поиска, подпись показывает, в какой исходный приём меню будет записана замена. Состав, нутриенты и ограничения проверяются перед записью.

Общедоступный прогресс получил самостоятельный выбор темы. Первый кадр наследует сохранённую тему приложения; явный выбор для страницы сохраняется отдельно. Системный режим реагирует на смену устройства. Светлые графики, выбранные точки, история, цели, формы, подтверждения и кнопки используют смысловые токены. Эта настройка не меняет аккаунт или его историю.

Добавлены проверки единственности выбора приёма, отсутствия повторов продуктовых кнопок, сохранения контекста замены, светлой темы клиентской страницы, восстановления выбора и реакции на системную тему.

Браузерная проверка v509 выявила старые селекторы .pp-point-chip.on, которые перекрывали семантический текст выбранной карточки. В v510 их приоритет исправлен; число и дата используют основной/вторичный текст.
