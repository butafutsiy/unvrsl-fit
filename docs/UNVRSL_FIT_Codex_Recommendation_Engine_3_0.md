## 1. Цель и границы

Система отвечает на четыре независимых вопроса:
1. START: с каким весом начать упражнение сегодня.
2. LIVE: что поставить в следующий невыполненный подход.
3. NEXT_SESSION: какой стартовый вес предложить на следующем сопоставимом занятии.
4. PHASE_CHANGE: какой вес соответствует новой фазе, повторениям или роли подхода.

Отдельный режим CALIBRATION подбирает стартовую нагрузку при отсутствии истории.
Отдельный режим TEST ведёт разрешённые контрольные попытки.

Килограммы не назначаются по росту, полу, возрасту или названию мышцы. Личные результаты и конкретное оборудование являются основой расчёта. Категория упражнения задаёт ограничения и исходную стратегию.

Проценты, коэффициенты коррекции, пороги и окна истории в этом документе – версионируемые инженерные эвристики. Они не являются доказанной индивидуальной физиологической моделью. Не называть их «научно точными» и не обещать безопасность на основании числа RIR.

Не менять автоматически упражнения, число дней или замысел программы. Не превращать авторские программы в один универсальный восьминедельный цикл.

## 3. Полное покрытие упражнений

### 3.1. Полнота означает весь фактический реестр

Приложение использует не только 189 строк базового файла. Построй итоговый реестр после добавлений, алиасов, виртуальных упражнений и карточек из программ.

Обязательные множества:
- canonical: актуальные записи основного каталога;
- additions: добавочные и виртуальные упражнения;
- programReferences: упражнения всех встроенных программ;
- custom: пользовательские упражнения;
- archivedReferences: старые ID, встречающиеся в сохранённой истории.

Сформируй exercise-profile-coverage.json и читаемый отчёт:
id, name, canonicalId, family, movementKind, loadAccounting,
progressionMetric, e1rmPolicy, profileStatus, reviewReason, source.
Каждая строка должна быть resolved, provisional либо manual_only.
Статус unresolved недопустим для выпуска. Неизвестная запись получает manual_only, а не случайный тип compound.
Это проверяемое покрытие, но provisional/manual_only не считать проверенной точной моделью.

Не заявляй «проверены все упражнения», если проверен только статический основной файл.
Приложение А даёт профиль по каждой из 189 исследованных записей. Сверь его с актуальным реестром; новые ID дополни и включи в отчёт.

### 3.2. Порядок выбора профиля

1. Подтверждённый override по стабильному exerciseId + variantId.
2. Явные структурированные метаданные canonical записи.
3. Подтверждённый alias к canonical ID.
4. Миграционная эвристика по названию/оборудованию с provisional статусом.
5. manual_only, если однозначного ответа нет.

Регулярные выражения нельзя оставлять главным классификатором рабочих расчётов.
sourceName – свидетельство для аудита, не автоматический приоритет над именем.
Нельзя молча переименовать ID или привязать историю к другому движению.

### 3.3. Раздельные признаки

movementKind: compound | isolation | skill | ballistic | isometric | cardio | mobility.
equipmentKind: barbell | smith | dumbbell | kettlebell | cable | selectorized |
plate_loaded | bodyweight | band | other.
loadAccounting: external_total | per_implement | per_side | stack_display |
bodyweight_added | bodyweight_assisted | partial_bodyweight |
external_only_proxy | none | unknown.
resultMetric: reps | seconds | distance | pace | power | rounds | mixed.
e1rmPolicy: local_proxy | system_mass_proxy | disabled.
profileStatus: resolved | provisional | manual_only.

Не смешивать односуставность с устойчивостью. Изоляция в тренажёре и махи стоя имеют разные ограничения.
Профиль F не определяет единицы: они задаются loadAccounting и equipmentSnapshot.

0 и null не взаимозаменяемы:

- вес пустой штанги не равен нулю;
- статус skipped не равен failed_attempt;
- неизвестный RIR не равен отказу.

минимума, соглашения «вес блинов/вес с грифом», серийного/локального ID тренажёра.
Исторический снимок не изменяется при редактировании оборудования.

## 5. Нормализация RPE/RIR и повторений

Использовать только силовую RIR-based RPE для силовых подходов.
RPE 10 → RIR 0; 9 → 1; 8 → 2; 7 → 3; 6 → ориентировочно 4.
RPE 9.5 → оценочный RIR 0.5 с отображением «0–1», без заявления о точности.
Кардио RPE/session RPE хранить отдельно, не переводить автоматически в RIR.

Порядок:
1. Валидный actualRir, включая 0.
2. Иначе валидный actualRpe силы 6–10 → 10 - RPE.
3. RPE 1–5 → effortKnown=true, effortPrecision=coarse, только качественная оценка.
4. Старое RPE 0, пустая строка, NaN → effortKnown=false.
5. Одновременно введённые противоречивые RIR/RPE → review; не выбирать молча удобное.
6. RIR «5+» → censored, точного значения нет.
7. Пропуск actual поля не даёт права использовать запланированное усилие как фактическое.

Десятичные запятая и точка допустимы. Boolean не преобразовывать в число.
Повторы – целые неотрицательные. Ноль при попытке должен иметь статус failed_attempt.
«24 суммарно» и «12 на ногу» имеют отдельную модель счёта. Для силы используются 12 на сторону.
Если суммарное нечётное число не позволяет восстановить стороны, не делить с ложной точностью.
Темп представлять четырьмя именованными фазами; миграцию старых трёх чисел документировать.
Смена темпа/амплитуды меняет сопоставимость, а не даёт универсальный процент поправки.

## 6. Приоритеты назначения

Независимо разрешать повторения, усилие, число подходов, темп и вес.

Приоритет плана:
1. Явное назначение подхода тренером.
2. Явное назначение упражнения.
3. Профиль метода и роли подхода.
4. Фаза/роль дня и профиль недели.
5. Семейство упражнения.
6. Безопасный ручной fallback.

LIVE не перезаписывает исходное назначение тренера.
Ручное изменение спортсмена относится к текущему будущему подходу, пока он явно не выбрал другую область.
Автовес заполняет неназначенное. Заданное тренером значение показывается с отдельной рекомендацией.
Нулевой внешний вес в подтягиваниях может быть явным назначением тренера.

plannedDeload – явное поле. Не считать любую нагрузку 60–65% разгрузкой.
plannedTest – явная роль попытки. Не делать все упражнения восьмой недели максимальными.

При конфликте процентов и повторов/RIR:
- определить, от чего проценты: e1RM, measured1RM или trainingMax;
- для strength-percent программы сохранять главный процентный план, показать конфликт;
- для RIR/double-progression главным является диапазон повторов и RIR;
- сохранять исходные значения, не исправлять без следа;
- при неразрешимом конфликте review, а не два конкурирующих веса.

## 8. Учёт нагрузки и оборудование

### 8.1. Четыре разные величины

displayedLoad – что спортсмен вводит.
modelLoad – условная нагрузка в локальном прогнозе.
externalTonnageLoad – внешняя нагрузка для тоннажа.
difficultyDirection – направление роста трудности.

Не подменять их одной переменной.

| Учёт | Отображение | modelLoad | Ограничения |
|---|---|---|---|
| external_total | Полный вес | displayedLoad | Для штанги с учётом согласованной массы грифа |
| per_implement | Вес одной гантели/гири | Вес одного снаряда | implementCount влияет на тоннаж, не удваивает прогноз «на руку» |
| per_side | Вес на сторону | sides × displayed + knownBase | Только при известных конфигурации и базе; иначе локальный proxy или manual |
| stack_display | Число на стеке | То же число как локальный proxy | Не объявлять физической силой; сравнивать одно устройство |
| bodyweight_added | Дополнительный вес | bodyMass + added | Только подходящие подтягивания/брусья, ориентировочно |
| bodyweight_assisted | Помощь | bodyMass - assistance | Только известный аппарат; значение должно быть >0 |
| partial_bodyweight | Отжимания/часть тела | Неизвестно без калибровки | Не использовать автоматически всю массу тела |
| external_only_proxy | Диск/гантель в гиперэкстензии и т.п. | Не использовать для общего e1RM | Можно отслеживать повторы и внешний вес |
| none/unknown | Время/повторы/неизвестно | null | Формула веса не запускается |

Тоннаж подтягиваний с весом: внешнее отягощение × повторы, если это выбранная существующая метрика приложения. Массу тела не добавлять к внешнему тоннажу.
Для гравитрона не считать «помощь × повторы» поднятым внешним тоннажем.
Если продукт хочет альтернативную метрику перемещённой массы – отдельное поле и название.

### 8.2. Оборудование

availableLoads – предпочтительный источник. Он может быть неравномерным.
Например, [5, 7.5, 10, 12, 14, 16, 18, 20, 22.5, 25].
Иначе: min + n × step, n целое, при известных min, max и step.
Для штанги учесть парность дисков; один диск 1.25 кг даёт +2.5 кг полного веса.
Для пары гантелей переход 30 → 32 означает +2 кг на гантель, а не +4 в поле веса.
Для кроссовера отдельные независимые стеки, одна общая тяга и две рукояти – разные конфигурации.
Для Смита: вес грифа с противовесом может быть неизвестен. Не подставлять автоматически 20 кг.
Для машин: геометрию рычагов/тросов не угадывать; не вводить универсальный коэффициент 0.60.
Для жима ногами не вычислять «реальные килограммы на мышцы» по одному углу 45°.
При неизвестной базе допустим локальный учёт блинов одного устройства с явной маркировкой proxy; запрет межмашинного переноса.
Смена устройства сохраняет историю, но начинает новую сопоставимую группу.

### 8.3. Кандидаты

Нельзя использовать max(step, capPercent × weight), чтобы легализовать большой скачок.
Обычный набор кандидатов содержит текущий вес, даже если доступного нового шага нет.
Микрошаги не выдумывать.
Повышение 8 → 10 кг в махах = +25%: обычная LIVE-прибавка блокируется.
Для NEXT_SESSION такой переход разрешён только при подтверждённой истории и попадании прогноза в нижнюю границу нового диапазона либо ручном решении.
При снижении большой шаг может быть разумнее сохранения чрезмерной нагрузки. Предлагать его явно как recovery fallback, без автоматического применения и без обещания точного RIR.

## 9. Сопоставимость истории

Строгий ключ:
athleteId + canonicalExerciseId + variantId + equipmentProfileId +
loadAccounting + ROM protocol + tempo class + methodId + setRole +
groupPosition + assistanceProtocol.

Группировать отдельно по:
- straight sets, top set, back-off, test;
- тяжёлой/лёгкой фазе UNVRSL;
- сегменту дроп-сета или rest-pause;
- стороне и номеру раунда;
- обычному упражнению и тому же упражнению внутри суперсета.

Изменение повторов/цели не делает историю бесполезной: это отдельный PHASE_CHANGE-прогноз с меньшей уверенностью.
Не переносить точный рабочий вес между HB/LB, Смитом/свободной штангой, разными хватами и тренажёрами.

Исключать из e1RM:
разминку, пропуски, незавершённые сеты, помощь партнёра, боль,
invalid технику, незапланированную частичную амплитуду,
неизвестное усилие, censored RIR, силовые данные другого пользователя,
несопоставимый аппарат, паузы rest-pause как отдельные свежие сеты.

Плановая partial ROM допускается только как свой variantId; не смешивать с полной.
По умолчанию усилие unknown/technique unknown не даёт high confidence.

### 9.1. Окна и свежесть

Для START/NEXT_SESSION использовать последние 5 сопоставимых тренировок за 90 дней.
Для численного прогноза достаточно последних 3 подходящих сессий.
Окна настраиваемы, версия фиксируется.
Не читать будущие по performedAt записи и текущий незавершённый сет.
Текущие completed подходы допустимы для LIVE, но не дублируются как отдельная прошлая тренировка.
Дубликаты cloud/local объединять по ID и ревизии, не суммировать.

Перерыв 14+ дней: low/medium confidence, предложение консервативного старта и калибровочного подхода.
Перерыв 28+ дней или крупное изменение устройства/варианта: новый provisional baseline.
Не снижать силу автоматически на фиксированные проценты за каждый день отсутствия.

### 9.2. Оценка локального e1RM

Для обычных подходов 3–12 повторений при известном RIR 0–4:
E = modelLoad × (1 + (reps + RIR)/30).
Для 13–15 повторений – только low confidence local proxy.
Для 16–20 и выше – использовать историю в том же диапазоне, не переносить в тяжёлые попытки через e1RM.
Для одиночек/двоек допустим отдельный низкоповторный proxy, но не повышать confidence без истории.
Формула не измеряет истинный 1ПМ и не заменяет профиль конкретного человека.
Для F18/F21–F27 e1RM отключён по умолчанию независимо от числа повторений.

Сессионная оценка: медиана валидных ранних (первых двух) ordinary рабочих подходов,
без back-off и предварительного истощения. Если валиден один – использовать один.
Top set имеет отдельный ряд.
Не выбирать автоматически максимальный выброс из всей тренировки.
Стабильная оценка: взвешенная медиана сессионных оценок последних 3 сессий:
самая новая 0.5, предыдущая 0.3, третья 0.2; при меньшем числе нормализовать веса.
Изменение сессионного proxy >10% от стабильного – provisional outlier до подтверждения.
Такая запись остаётся в истории, не стирается.

Снижение поздних подходов не уменьшает свежий baseline напрямую.
Персональную зависимость «вес – повторы – RIR» вводить только после минимум 12 валидных сетов
из минимум 4 сессий и двух диапазонов повторений. До этого не подгонять сложную кривую.

## 10. Confidence

High:
минимум 3 сопоставимые сессии, минимум 6 валидных сетов,
актуальное оборудование, повторяемый результат, последняя сессия ≤21 дня,
известны фактические усилие и качество. Это доверие к данным, не гарантия результата.

Medium:
1–2 сопоставимые сессии либо ≥2 валидных подходов сегодня при подтверждённом профиле.

Low:
новое упражнение, provisional профиль, смена диапазона, давняя история,
один сет, высокий rep count, неизвестный отдых, RIR coarse.

None:
неизвестная нагрузка, конфликт метаданных, отсутствуют цель и факт,
censored усилие для точной формулы.

confidence должен объясняться флагами, не выдуманным процентом «точность 97%».

## 11. LIVE: детерминированная коррекция при прежней цели

Применять этот алгоритм только при одинаковой роли, методе, сопоставимом отдыхе и новой цели
в том же диапазоне. Изменение повторений по плану направлять в PHASE_CHANGE.
Примеры килограммов из PDF 2.0 не являются независимыми константами:
таблицы должны генерироваться алгоритмом и доступным оборудованием.

### 11.1. Порядок защит и диагностик

1. painFlag или stopReason=pain → stop; suggestedWeight=null.
2. invalid техника, неконтролируемая амплитуда, вмешательство партнёра → review/stop,
   без повышения и без оценки силы.
3. Ноль выполненных повторений после реальной попытки → failed_attempt;
   не вычислять e1RM. Предложить отдых/проверку/облегчение вручную.
4. warmup/skipped → no update.
5. F00 или конфликт единиц/оборудования → review.
6. Ранний stopReason=interruption/balance/breathlessness/grip → отдельное объяснение,
   не считать доказанным снижением силы целевой мышцы.
7. Нет фактического усилия → no precise calculation; допускается рекомендация повтора веса.
   Повторный недобор ниже минимума без RIR может дать qualitative easier с low confidence,
   но не выдуманное «точно 92.5 кг».
8. RIR 5+ или RPE<6 → coarse: никакой точной формулы.
9. plannedDeload/allowLoadIncrease=false → запрет автоматического повышения.
10. После проверок анализировать повторы и усилие.

### 11.2. Попадание в прямоугольник цели

Цель: повторы [a,b], запас [c,d], где a≤b и c≤d.
Факт: r, q. При чистом выполнении P = r+q – грубый потенциал.

Если r ∈ [a,b] и q ∈ [c,d]: hold.
Если r<a, q>d и подход прекращён раньше мышечного лимита:
hold + подсказка выполнить минимум повторений; не повышать и не снижать автоматически.
Если r>b и q<c, но P лежит в [a+c,b+d]:
hold + предложить остановиться раньше. Например, цель 10/RIR2, факт 12/RIR0.
Это коррекция поведения, не подтверждение плохого веса.

Если существует rNext ∈ [a,b], для которого P-rNext ∈ [c,d],
сохранить вес и рекомендовать такой rNext с приоритетом текущего разрешённого rep target.
Не требовать достигнуть верхней границы в каждом сете.

Если P < a+c: shortage=(a+c)-P.
Если P > b+d: excess=P-(b+d).
Порог обычной коррекции: gap≥2.
При gap<2: hold с reason=within_estimation_tolerance.
Это не переименовывает недобор в успешное выполнение.
Для явно избыточного технического риска/повторного отказа использовать защиту раньше порога.

Отказ при целевом RIR≥2 и низких повторениях в F01/F02/F03:
запрет повышения; при недостаточном gap и выраженной усталости review либо облегчение.
Не заставлять повторять отказ ради накопления подтверждений.

### 11.3. Величина коррекции

Для нехватки reference=a+c, для избытка reference=b+d.
fraction = gap / (30 + reference) × damping.
damping:
- easier: 0.66 при gap=2; 0.76 при gap≥3;
- harder: 0.60.
Ограничить fraction соответствующим family live cap.
desiredModelLoad = currentModelLoad × (1 ± fraction).

Это сглаженный вариант исходного отношения Эпли.
Не применять сглаживание второй раз в другом UI или readiness-модуле.
Для диапазона брать ближайшую нарушенную границу, а не всегда середину.

### 11.4. Округление

1. Получить доступные displayed-кандидаты.
2. Преобразовать каждый в modelLoad при той же конфигурации.
3. Отфильтровать недопустимые и нарушающие обычный cap.
4. Включить текущий вес как hold-кандидат.
5. Выбрать минимальное abs(candidateModelLoad - desiredModelLoad).
6. При равенстве выбрать меньшую абсолютную коррекцию; затем более лёгкий вариант.
7. Если выбран текущий вес – blockedByEquipment либо deltaBelowStep, не фиктивная прибавка.
8. Проверить обратный перевод и единицы.
9. Для помощи action определяется трудностью, не знаком displayed delta.

При выраженном shortage и отсутствии подходящего облегчения в cap:
recovery fallback = ближайшая реально более лёгкая ступень за пределом cap.
Показать её отдельно с low confidence и needsAcknowledgement=true.
Если даже минимум не подходит – stop/review/другой согласованный вариант.
Не выдавать «сохрани вес» как единственный ответ после явно неподъёмной нагрузки.

### 11.5. Проверочная матрица LIVE

Условия: ordinary жим, 100 кг, цель ровно 10/RIR2, чистая техника,
отдых соблюдён, step 2.5, F04, нет разгрузки.
Ожидаемые значения ниже следуют из 11.2–11.4 и не учитывают будущую усталость.

| Повторы | RIR0 | RIR1 | RIR2 | RIR3 | RIR4 |
|---|---:|---:|---:|---:|---:|
| 8 | 92.5 | 95 | 97.5 | 100 | 100 |
| 9 | 95 | 97.5 | 100 | 100 | 100 |
| 10 | 97.5 | 100 | 100 | 100 | 102.5 |
| 11 | 100 | 100 | 100 | 102.5 | 105 |
| 12 | 100 | 100 | 102.5 | 105 | 105 |

Ранний недобор при высоком запасе имеет hold-приоритет.
12/RIR0 требует подсказки остановиться на 10.
Не требовать разных килограммов для каждого соседнего RIR: дискретный ряд делает совпадения нормальными.
До выдачи рекомендаций для других упражнений заново применять их профиль и оборудование.

## 12. Усталость и отдых

Не вычитать фиксированные 5% «за каждый следующий подход».
Сначала учитывать:
- цель конкретного следующего подхода;
- фактический отдых;
- номер подхода и раунда;
- запланированное падение повторений;
- сопоставимые серии человека.

Серия 10/10/9/8 при диапазоне 8–12 не является недобором сама по себе.
Серия 10/9/7/5 при минимуме 8 – сигнал к проверке отдыха и коррекции поздних сетов.

Если actualRest <80% от назначенного:
пометить short_rest; не снижать долгосрочный baseline.
LIVE-облегчение всё ещё допустимо, если сейчас выполнить цель не получается.
Не гарантировать, что увеличение отдыха само исправит результат.

До накопления 3 сопоставимых полных серий отдельную персональную кривую утомления не применять.
После 3 серий можно использовать медиану относительного падения по номеру подхода,
но не переносить её между обычными сетами, суперсетами и rest-pause.
Самочувствие используется для консервативного старта или предложения пересмотра объёма.
Не умножать вес на readiness factor повторно в каждом обработчике.

## 13. NEXT_SESSION: стратегии прогрессии

Успешный сет: минимальные повторы выполнены, усилие не выше разрешённого,
техника пригодна, амплитуда соответствует протоколу.
Неизвестное усилие не считать автоматически успешным для RIR стратегии.

### 13.1. DOUBLE_PROGRESSION – основной режим гипертрофии

1. Сохранять вес, пока не освоен диапазон во всех запланированных ordinary рабочих сетах.
2. Повышать целевые повторы в пределах диапазона, не обещая +1 в каждом сете.
3. Готовность к прибавке: все назначенные рабочие сеты на этом весе дошли до верхней границы
   при RIR не ниже разрешённого минимума, без invalid техники.
4. При step≤5% и medium/high confidence достаточно одной полной успешной сессии.
5. При step>5%, provisional профиле или low confidence – минимум две сопоставимые успешные сессии
   и прогноз попадания нового веса в нижнюю границу.
6. Прибавка – одна реальная ступень, а не обязательный заданный процент.
7. После прибавки повторения возвращаются в нижнюю часть диапазона.
8. Один поздний недобор: hold стартового веса, отдельная LIVE-коррекция.
9. Повторные ранние недоборы в двух сопоставимых сессиях: рассмотреть одну ступень вниз,
   если отдых и техника не объясняют проблему.
10. Неполная тренировка не подтверждает готовность к росту.

Не использовать автоматически правило «75% подходов достаточно» для всех программ.
Если тренер хочет такой критерий, это явный параметр successFraction, default=1.0.

### 13.2. LINEAR_SETS – 5×5 и подобные

Успешное выполнение всех назначенных сетов → одна настроенная прибавка на следующее появление.
Один недобор → повтор веса по правилам программы.
Повторные неудачи → её правило reset/deload, а не общий алгоритм плато.
StrongLifts-подобный default: 3 последовательные сопоставимые неудачи → предложение −10%.
Не приписывать это правило всем силовым программам.
RPE помогает диагностике, но не отменяет авторскую стратегию задним числом.

### 13.3. RIR_AUTOREGULATED

Старт по сопоставимой истории; LIVE корректирует под заданный RIR.
NEXT_SESSION использует ранние рабочие сеты и полную серию.
Случайный сверхлёгкий подход не повышает долгосрочный baseline без подтверждения.
Порог e1RM-прогресса не использовать как единственный критерий.

### 13.4. PERCENT_PERIODIZED

Явно хранить referenceType: measured1RM|estimated1RM|trainingMax.
trainingMax – отдельное число, не синоним 1ПМ.
Нагрузка = reference × plannedPercent, затем оборудование.
RPE – обратная связь и основание предложить коррекцию, а не тихо переписать проценты.
Переход 12 → 6 повторений не ограничивается live cap.
Отсутствие актуального reference → калибровка или ручной ввод.

### 13.5. COACH_PRESCRIBED / MANUAL

Тренерский вес остаётся планом.
Показывать отдельный совет по истории до тренировки и после выполненного сета.
Кнопка применения меняет только выбранный будущий сет/область.
Никаких скрытых постоянных изменений клиентской программы.

### 13.6. AMRAP

Хранить minReps и stopRir отдельно.
AMRAP не означает обязательный мышечный отказ.
Контрольный AMRAP относится к специальной роли.
Процент пересмотра trainingMax задаёт стратегия программы, не формула LIVE.

### 13.7. Плато и разгрузка

Три одинаковых e1RM не доказывают плато.
Сначала проверить прогресс повторений, техники, амплитуды и числа качественных сетов.
Если минимум 3 сопоставимые экспозиции без прогресса и минимум 2 независимых признака
усталости/повторных неудач – предложить review объёма/нагрузки.
Не назначать всем −7.5% автоматически.
Различать reset одного упражнения и разгрузку программы.
Сохранять предложение отдельно от факта принятия.

## 14. PHASE_CHANGE и конфликт процентов

Если меняется диапазон повторов, сначала найти историю в целевом диапазоне.
Если её нет, использовать допустимый локальный proxy с low/medium confidence.

Для допустимой формулы:
desiredLoad = E_stable / (1 + (rTarget + qTarget)/30).
Для диапазонов получить нагрузочный коридор:
lower = E / (1 + (repMax + rirMax)/30);
upper = E / (1 + (repMin + rirMin)/30).

Выбирать реальную ступень внутри коридора, ближайшую к последнему подтверждённому
весу для этой роли. При отсутствии такого веса – к середине коридора.
Не выбирать автоматически верх коридора из-за названия Heavy.
Если реальных ступеней внутри нет – показать конфликт оборудования и ближайшие варианты.

Сдвиг >20% от последнего сопоставимого рабочего веса или прогноз из 13–15 повторений в 1–3:
review/калибровка, без автоматического заполнения тяжёлой попытки.
Переход с изоляции на 1ПМ не генерировать.
1–3 повторения на 100% актуального measured1RM:
одиночка возможна как тест, тройка конфликтует с назначением.
Не применять модель Эпли как физиологический закон при валидации процентов:
это проверка правдоподобия, предупреждение с объяснением.

## 15. CALIBRATION: когда веса и истории нет

Не назначать пять тяжёлых попыток и не тестировать до отказа все диапазоны 12/10/8/6/4/2.
Первичный подбор делается в текущем рабочем диапазоне.
Личные проценты для остальных диапазонов сначала являются provisional прогнозом.

Порядок:
1. Выяснить/получить equipment profile и способ записи веса.
2. Подтвердить знакомство с упражнением. Незнакомое технически сложное – сначала техника,
   ручной выбор лёгкого старта, без тяжёлой проходки.
3. Пользователь/тренер выбирает лёгкую первую ступень из реального ряда.
4. Короткая разминка по упражнению, отдельно от рабочих данных.
5. Пробный сет на нижнюю границу текущего диапазона, остановка с ориентиром RIR 3–4.
6. При RIR 5+ и чистой технике предложить одну ступень выше; максимум две ступени
   только если общий переход ≤10% и это разрешено профилем.
7. При избыточной нагрузке – ступень ниже, восстановление.
8. Максимум три пробных нагруженных подхода за первое занятие. Если нужный вес
   не найден, сохранить provisional baseline и продолжить подбор на следующем занятии.
9. Один подход попал в цель → provisional baseline; подтверждение вторым подходом или следующей сессией.
10. Пробный подход, совпавший с рабочей целью, можно засчитать рабочим по явному решению.
    Не добавлять скрытый объём поверх плана.

Для F01/F02/F03 не требовать отказа для подтверждения RIR.
Для гравитрона калибровать помощь в обратном направлении.
Для 0 кг добавленного веса не выводить «нет данных», если подтягивания реально выполнены.
При большом скачке гантелей использовать повторы/микровеса; не вынуждать переход.
Проценты CALIBRATION не наследуются в качестве точной силы для тестовой недели.

## 16. Методы, связки и стороны

STANDARD: сравнение однотипных обычных сетов.
TOP_SET/BACK_OFF: разные роли и отдельные ряды. Back-off по назначению,
а не автоматически −10% от любого тяжёлого подхода.

SUPERSET/TRISET:
- стабильные groupId/groupPosition/roundIndex;
- переход между упражнениями и полный отдых после раунда – разные таймеры;
- RIR каждого упражнения отдельно;
- результаты одной позиции не сравнивать с выполнением первым отдельным упражнением;
- коррекция упражнения не ломает порядок связки;
- при остановке одного упражнения дать явный skip/review, не зависнуть в фокус-режиме.

UNVRSL 3+9:
- тяжёлая тройка → плановый переход → лёгкая девятка;
- каждый сегмент имеет собственный вес, повторы, RIR и роль;
- раунд 1/2/3 хранится;
- один сегмент не определяет вес другого через универсальный коэффициент;
- live коррекция применяется к следующему аналогичному сегменту;
- последующие средние ordinary сеты – отдельная роль.

SLDR/REST_PAUSE:
- один кластер, initialWeight, segments[], restWithin;
- первый сегмент пригоден для локального proxy лишь при валидности;
- последующие сегменты не считаются свежими сетами для e1RM;
- оценка totalReps не подставляется в обычную формулу Эпли;
- прогрессировать по целям кластера и первой части, не по каждому сегменту.

DROP_SET:
- initial segment и drop stages;
- веса каждой ступени доступны физически;
- отсутствие отдыха не даёт права интерпретировать позднюю ступень как падение baseline;
- не менять все ступени по результату одной без явного правила метода.

FST-7:
- семь сетов по назначению;
- сравнение полного семисетового блока с тем же отдыхом;
- позднее падение повторений ожидаемо, оценить выполнение минимума;
- не запускать автоматическую прибавку после каждого лёгкого раннего сета.

SIDES:
- левая и правая отдельно; повторы на сторону;
- общий вес по умолчанию одинаковый;
- рост только если обе выполнили критерии;
- при асимметрии подсказка по слабой стороне без назначения разных весов автоматически;
- боль одной стороны не усреднять;
- «две руки одной гантелью» имеет implementCount=1.

## 17. TEST и восьмая неделя

Тест не включается по одному номеру недели.
Разрешён только для выбранного упражнения, явной роли и достаточного опыта/истории.
Технически ограниченные упражнения могут иметь rep PR вместо максимального веса.
Румынская тяга, good morning, гиперэкстензия и изоляция по умолчанию не получают
автоматический тест истинного 1ПМ. Тренер может задать отдельный контролируемый протокол.

- Разминка отделена.
- Первая попытка выбирается консервативно по подтверждённым тяжёлым результатам.
- Следующая тяжёлая ступень появляется только после успешной предыдущей.
- При failed attempt, боли, invalid технике дальнейшая автоприбавка блокируется.
- Не записывать failed single как «0 повторений с тем же 1ПМ».
- Не обещать 105–110% истинного актуального 1ПМ как обычный рабочий вес.
- Сначала новый успешный результат, потом обновление measured1RM.
- Back-off получает собственное назначение.
- Вспомогательные упражнения сохраняют свои повторения/RIR и не наследуют RPE10.

## 18. Особые стратегии без 1ПМ

BODYWEIGHT:
рост повторений в диапазоне → освоение полного объёма → согласованное усложнение.
Переход варианта требует подтверждения и нового variantId. Не усложнять движение скрыто.

PARTIAL_BODYWEIGHT:
отжимания: высота опоры, положение ног/коленей, темп и внешний вес хранятся.
Без измерения не задавать общий коэффициент массы тела.
Гиперэкстензия: угол опоры/положение диска меняют сложность; история только сопоставимая.

ISOMETRIC:
прогрессия длительности в заданном диапазоне.
Удержание 30 секунд не переводить в 30 повторений.
Изменение рычага/нагрузки после освоения верхнего времени по явному протоколу.
Использовать субъективную сложность удержания, не утверждать RIR повторений.

BALLISTIC:
прогрессия качества, техники, количества качественных повторов и плотности по плану.
Ухудшение высоты/скорости/контроля → остановка серии.
Без валидированного датчика не генерировать численную потерю скорости из RPE.
Рывок гири: фиксировать вес, длительность/повторы, руку, смены; вес повышать только по протоколу.

CARDIO:
отдельные duration/distance/pace/incline/power и cardioRPE.
Один управляющий параметр на шаг прогрессии, остальные фиксированы.
Рост длительности до 5% или следующий заданный интервал допустим как настраиваемая
инженерная стратегия после двух выполнений цели; не универсальная физиологическая норма.
Для интервалов и соревнований использовать авторский протокол.
Не писать «прибавить 2.5 кг» бегу или скакалке.

BANDS:
идентификатор резинки, длина/натяжение, точка крепления, движение.
Номинальные «кг» производителя не считать постоянной нагрузкой по амплитуде.

MOBILITY/REHAB:
manual protocol, нет автоматического роста веса по RIR.
Система не создаёт лечебные назначения.

CARRIES/SLEDS:
вес, расстояние, время, поверхность/устройство; mixed metric.
Не объединять их с e1RM приседа или обычной тяги.

## 21. Интерфейс и применение

Единая карточка в активной тренировке и фокус-режиме:
- действие крупно: «95 кг», «Помощь 35 кг», «Оставить 8 кг»;
- цель: повторения и RIR;
- причина: план, факт, уровень уверенности;
- «Применить», «Оставить», «Почему»;
- область: следующий подход; другие области только по явному выбору;
- назначение тренера видно отдельно;
- смена assistance подписана словами «увеличить помощь/уменьшить помощь».

До тренировки:
при назначенном весе показать отдельную рекомендацию по истории;
при неназначенном – заполнить автовесом только при достаточных данных,
иначе «Подобрать вес». Не оставлять молчаливый ноль как рабочий совет.

После каждого обычного выполненного сета:
оценка попадания в цель и предложение для следующего подхода.
Последний сет: итог упражнения/следующая тренировка, без выдуманного следующего сета.

Применение:
- проверить inputFingerprint и актуальность targetSetId;
- выполненные и пропущенные сеты не менять;
- idempotent: повторное нажатие не добавляет проценты повторно;
- dismissed recommendation не появляется снова без нового факта или смены цели;
- вручную изменённый pending вес не перетирать новым событием загрузки истории;
- разрешить undo последнего изменения будущего веса;
- фиксировать source и originalPrescription;
- roundtrip offline/cloud сохраняет смысл.

Показывать целевые 12/нога, 30 кг/гантель, 20 кг/сторона.
Не отображать «точность 100%», «идеальный вес» и диагнозы усталости.
Причина должна объяснять ограничение: «Следующая гантель +25%; пока добавляем повторы».

## 22. Детерминированность, хранение и миграции

Расчётный core – чистые функции без DOM, времени, сети и изменения входов.
Время передаётся параметром now; сортировка стабильная, ties разрешены явно.
Одинаковые нормализованные входы + engineVersion дают одинаковый результат.

Фактические подходы после завершения неизменны без явного редактирования истории.
Сохранение программы и сохранение завершённой тренировки – разные операции.
Миграции:
- идемпотентны;
- имеют schemaVersion;
- не выдумывают actualRir из targetRir;
- старое RPE0 → null, только если это подтверждённый sentinel;
- не меняют старый вес из «на руку» в «сумма» без признака старой единицы;
- неоднозначность → legacyUnknown + review;
- не пересоздают удалённые программы;
- сохраняют exerciseId и provenance алиасов;
- не загружают данные одного пользователя в рекомендации другого.

Поддержать десятичную арифметику без дрейфа при повторном сохранении.
Допуск сравнений ≤1e-6, форматирование отдельно.
Кеш рекомендаций содержит engineVersion и fingerprint; при смене версии пересчитывается.
Обновление service worker не должно оставлять старый JS расчёта рядом с новым UI.

A75. Все вычисления конечны; никаких NaN/Infinity/выдуманных ступеней.
A76. Большой step не повышает разрешённый cap автоматически.

## Приложение Г. Алиасы и упражнения программ, отсутствующие как самостоятельные записи

Следующие строки являются заданием на canonical resolution. Не создавать дубликаты без проверки.
- «Присед HB», «Приседания со штангой» → подтверждённый HB либо явный вариант тренера;
  «просто присед» не доказывает HB, если история не уточняет.
- «Жим лёжа», «Жим штанги лежа» → canon:bench_press после проверки оборудования.
- «Жим гантелей на наклонной» → canon:incline_db_press.
- «Верхний блок», «Тяга вертикального блока» → canon:lat_pulldown при совпадении варианта.
- «Нижний блок», «Тяга горизонтального блока» → canon:seated_cable_row.
- «Махи в стороны», «Подъём гантелей в стороны» → canon:lateral_raise.
- «Тяга одной рукой в блоке» → уточнить горизонтальную/вертикальную траекторию, не угадывать.
- «Бицепс», «Махи», «Икры», «Брусья», «Ягодичный мост» → недостаточно для точной
  идентичности без оборудования/варианта; использовать явную привязку программы.
- «Разводка / бабочка» и «EZ / скамья Скотта» – альтернативы, не одно упражнение.
  Спортсмен выбирает вариант, каждый имеет собственную историю.
- B-stance RDL, одноногая RDL → отдельный variantId/F03, per-side, не сливать с двуногой.
- Мост с гантелью → F11, per_implement count1.
- Мост одной ногой → F22 либо F11 с внешним весом, отдельный variantId.
- Отведение бедра с резинкой → F26, не F13 с фиктивными килограммами.
- Отжимания на полу/с опоры/с колен/с весом → отдельные варианты F21/F22.
- Face Pull/тяга к лицу → F15, stack_display, конкретная рукоять/устройство.
- Французское разгибание, разгибание из-за головы → F14 с уточнением снаряда.
- Зашагивания, выпады без указания снаряда → resolve по назначению, не подставлять две гантели.
- Аэробайк W1/W8 и другие недельные суффиксы → тот же cardio ID;
  роль разминки хранится отдельно от идентичности упражнения.
- «Тест попытка 1», «back-off 70%» – setRole, не новый canonicalExerciseId.
- Подписи «на руку», «на ногу», «суммарно» – структурированные единицы,
  не часть строки, которую каждый модуль разбирает заново.

## Приложение Д. Параметры алгоритма и границы MVP

Собрать параметры в версионируемый конфиг:
engineVersion=3;
sameTargetGapTolerance=1;
liveGapThreshold=2;
downDampingSmall=0.66;
downDampingLarge=0.76;
upDamping=0.60;
historySessionLimit=5;
historyWindowDays=90;
estimateSessionLimit=3;
estimateWeights=[0.5,0.3,0.2];
proxyPrimaryRepRange=[3,12];
proxyLowConfidenceRepRange=[13,15];
proxyOutlierFraction=0.10;
phaseChangeReviewFraction=0.20;
calibrationMaxLoadedTrials=3;
successFractionDefault=1.0.

Порог gap>=2 является правилом по умолчанию, защитные состояния имеют приоритет.
Равенство накопленного веса 0.5 при взвешенной медиане:
взять середину текущего и следующего по возрастанию значения.
Отдельно протестировать равные значения и меньше трёх сессий.

Персональная кривая, прогноз утомления и самонастройка коэффициентов – расширения:
не включать их с выдуманной статистикой. Если данных недостаточно, базовый алгоритм
должен полностью работать без них. Архитектура и поля для накопления данных обязательны.

Никакой алгоритм не определяет технику по одному числу RIR. Если техника не оценена,
это должно оставаться неизвестным, а не автоматически «чисто».
